## Summary

OSMA v0.1.0 is a local mentor for developers who want to contribute to Bitcoin open-source projects. It runs on your machine. Guide mode is the default: leave `OPENAI_API_KEY` empty and the curriculum, project guides, and GitHub tools still work. No language model is called.

A conversational mentor is optional. The default endpoint is Ollama on loopback (`llama3.2` at `http://127.0.0.1:11434/v1`). Cloud OpenAI is used only if you set that base URL, a cloud model name, and a real key yourself.

OSMA teaches the protocol and the review culture, then helps you find a first issue, plan a change, and read a pull request. It does not fork repositories, push commits, or open pull requests, and it will not ACK code you have not read.

## What is in this version

History below is the work on `main` that this candidate includes.

### Local mentor (31 October 2026)

Commit `58c7fc3` replaced an earlier hosted prototype with the app in this release:

- Next.js app (`apps/web`) for chat, the curriculum, and project pages.
- FastAPI service (`services/agent-api`) with a tool-calling mentor loop and a guide-mode path that uses the same tools.
- Lessons in the repository, not fetched from a content network: 8 Bitcoin fundamentals lessons, 3 Lightning lessons, and 8 contribution-craft lessons. Each lesson has a quiz. Answers stay hidden until you submit, and grading runs on the local API.
- Guides for Bitcoin Core, libsecp256k1, rust-bitcoin, rust-miniscript, BDK, LDK, LND, Core Lightning, BTCPay Server, and the Lightning BOLTs.
- GitHub client for public issue search, file reads, contribution plans, and pull-request review checklists.
- SQLite file for conversations (`sqlite:///./data/osma.db` under `services/agent-api`). No accounts.

Commit `58a3230`:

### CI and one-command setup (27 November 2026)

Commit `3a378b9`:

- GitHub Actions (`.github/workflows/ci.yml`) runs, on pushes to `main` and on pull requests targeting `main`:
  - API: `ruff check app tests`, `pytest`
  - Web: `npm run lint`, `npm test`, `npm run build`

- `make start` creates `.env` from `.env.example` when needed, installs missing dependencies, and starts the API and the web app.
- `make up` does the same env copy and runs `docker compose up --build`. Published ports bind to loopback.

## Install

Requirements for `make start`: Python 3.11+, Node.js 22, and git. Ollama is optional. Docker is required only for `make up`.

```bash
make start
```

- Web: http://127.0.0.1:3000
- API: http://127.0.0.1:8000

Guide mode needs nothing else. The empty key in `.env.example` is enough.

```bash
make check
```

## Known limits

- No accounts. Anyone who can open the port can read the SQLite conversations. Keep the app on localhost. See `SECURITY.md`.
- Guide mode follows phrases and tools. It is not a free-form tutor.
- Public GitHub lookups leave the machine even in guide mode. A token is optional and env-only.
- From inside Compose, `127.0.0.1:11434` is the API container, not Ollama on the host. Leave the key empty, or set `OPENAI_BASE_URL=http://host.docker.internal:11434/v1`.
- English only. No offline model bundle is packaged. Nostr and ecash are not in the catalog yet. See `docs/ROADMAP.md`.
